# Practical guides — Kestro

The owner requested useful tutorials inside the existing website, after rejecting
rotating mock hardware and repeated overview grids. `/vejledninger` remains the
knowledge hub; established articles and their URLs remain available.

## Direction

Production implementation using Kestro's existing navy, royal blue, Jakarta type
scale, shared navigation, plates and light sheets. The light practical section
separates an immediate task from the longer editorial library. One larger slow
computer guide provides a starting point; three compact photographed entries go
straight to battery, memory and storage tasks. No durations, popularity badges,
invented prices or automatic device-detection claims.

The reference material informed reading hierarchy (Mintlify) and restrained
hardware photography (Apple), while the real repository's brand rules determine
the implementation. Those identities are not copied.

## Layout and interaction

- Each guide has one answer-first introduction, one contextual photograph, four
  connected steps, a relevant tool where available, two interpretation points,
  related actions and primary documentation.
- The mobile step spine remains visible. Four steps use four columns only where
  they fit; the interpretation uses two columns for its two points.
- Hardware images retain their 4:3 frame. They are identified as AI illustrations
  and never presented as model-specific installation instructions.
- Topic cards are full links. Tool controls have native labels, clear focus,
  inline validation and results invalidated on input changes.
- Battery and RAM calculators use entered figures locally. The optional browser
  check is opt-in, bounded and cancellable; it does not report hardware health,
  CPU frequency or RAM speed.
- Danish and English routes share canonical/hreflang, sitemap and search data.

## Verification

The release gate remains `npm run verify`, including content, production build,
browser structure/contrast/motion checks and security checks. Focused checks cover
the practical tools, stale values, cancellation and narrow/wide overflow. Results
and deployment evidence belong in the delivery note, not in customer copy.
