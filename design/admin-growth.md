# Kestro growth workspace

The owner needs to answer three questions: where did visits arrive from, what
did Google show, and which links should be used next? This is a private working
tool, with three destinations under Vækst: Trafik & kilder, Google & SEO and
Kampagnelinks. Customer correspondence keeps its existing daily-work navigation.

## Intent and craft checkpoints

The previous acquisition feature set scores 5/10 against this task: basic source
labels existed, but campaign context and search-query reports did not. That is
a scope-specific baseline, not a claim that the existing inbox is defective.

The domain is an arrival ledger, a search-performance notebook and a link
workshop. Kestro navy frames paper analytical surfaces; ink figures, quiet steel
metadata and a single blue intent colour establish hierarchy. The signature is
the source/evidence ledger beside an explicit coverage statement. No ornamental
score, rotating hardware, fictional map or invented live integration.

| Checkpoint | Implementation decision                                                              |
| ---------- | ------------------------------------------------------------------------------------ |
| Hierarchy  | Sources first, then campaigns and entry pages. Live activity is secondary.           |
| Density    | Short introductions, progressive disclosure for methodology and import details.      |
| Surface    | Paper work surfaces inside the existing navy shell; one dominant table.              |
| Type       | Existing Jakarta, tabular figures, stable heading levels and readable metadata.      |
| Controls   | Native URL filters, at least 44px controls, explicit focus and result states.        |
| Mobile     | First source and key coverage remain reachable; tables get labelled local scrolling. |
| Motion     | No decorative entrance motion; reduced-motion preference remains supported.          |
| Data       | Visits, Google clicks and Google impressions retain separate meanings.               |

The interface-design and UI/UX skills informed this direction. Two local UI/UX
searches returned useful Swiss/data-density principles but marketing-page
patterns inappropriate for an internal tool. Those page patterns, extra fonts
and decorative motion were rejected in favour of this project-specific brief.

## Ten acceptance criteria

Each criterion earns one point only with implementation and verification. A
passing implementation checklist is not a guarantee of commercial outcomes or
universal aesthetic perfection.

1. Canonical source/channel attribution with unknown and historical evidence.
2. First-session attribution, reload deduplication and no enquiry identity join.
3. Common-denominator 7/30/90-day filters and comparable prior windows.
4. Campaign/placement and entry-page tables plus private CSV export.
5. A working link builder with published destinations and clipboard fallback.
6. Real Search Console query/page/date reports, with freshness and privacy gaps.
7. Validated preview/import, idempotent report replacement and private backup.
8. Three clear growth destinations with desktop and phone layouts.
9. Keyboard, contrast, overflow, unavailable/empty/error states checked in browser.
10. Middleware/page/API/database gates, CSRF and bounded inputs tested.

Actual Search Console reports remain outside source control. Production data
loading is checked separately from synthetic test results. Instagram referral
does not establish Explore discovery; utm_content is a declared link placement.
Google query tables are aggregate reports and never a named visitor's history.

## Verification record

21 October 2026: the mandatory `npm run verify` gate passed on the combined
growth implementation and the separately published Mak SEO changes (5afc21b).
The run includes 216 security checks, all public-template checks, seven admin
workspace scenarios and twelve synthetic admin workflows. The new pure-data
suite passes 21 check groups. Production backend functions also passed nine
groups against actual isolated PostgreSQL through Neon's serializer, including
concurrent visit creation, rollback, exact denominators and report replacement.

The ten implementation criteria above pass. This is a 10/10 acceptance
checklist, not a claim of aesthetic perfection or guaranteed traffic growth.
The independent visual review identified two material phone-layout issues:
the first source was below the initial viewport, and report metadata obscured
access to search queries. Both were addressed; the source is now asserted in
the initial 390px viewport, and query access has a dedicated jump control.
The same review also led to bounded native file inputs, darker placeholders,
preserved active filters, keyboard table scrolling and safe landing links.

Responsive captures live outside the public repository under
`outputs/growth-review/`. Real Search Console data and production-import proof
are kept there separately from synthetic screenshots. A successful local test
is never presented as evidence that a production account is connected.
